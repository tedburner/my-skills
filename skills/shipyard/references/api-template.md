# HTTP 接口条目模板

在 LLD 中为每个新增或修改的“方法 + 路径”建立独立编号条目。CRUD 的新增、列表、详情、修改、删除分别展开；同一接口的不同筛选条件不拆成多个点。条目放在所属模块下，锚点和编号接续 LLD 现有编号，标题使用业务名称。

下方“创建资源”仅演示版式和字段、示例的一致关系，不是任何项目的真实协议。使用时替换名称、编号、回链、方法、路径、包装及字段；沿用项目已有路由和错误处理风格，不强制 REST。标题只保留确认状态、编号和业务名称，参数与路径放正文；条目内默认用独立加粗标签，避免每个接口向目录增加多层重复栏目。

没有依据的契约标记待定。未解决时用 `[ ]` 标题，开头按“要确认 / 建议”分别列短列表，后续契约注明哪些是拟议值；已决定时用 `[x]` 标题，开头按“结论 / 依据”陈述。部分已确定时仍保持 `[ ]` 并列明剩余问题，不同时留下两套有效结论，也不要求用户逐个确认常规接口。

按以下方式适配内容：

- 请求参数标明 Path、Query、Header 或 Body；请求的必填与允许 null 分开表达，响应的必有与允许 null 也分开表达。嵌套字段使用完整路径，如 `items[].id`。复杂约束放在表后，不塞长段落进单元格。
- 请求示例包含实际方法、路径、必要 Header 及 Body；路径和查询参数展示具体示例值，凭据只用占位符。无入参时明确写“无”，无请求体时不补 `{}`。
- 成功响应给完整示例，外层包装、分页字段、数组和 null 与字段表一致；无响应体时注明实际 HTTP 状态和“无响应体”。文件、流式或其他非 JSON 响应按真实格式展示，不伪造 JSON。
- 公共约定回链到已存在的设计点，本点只补差异。错误表区分 HTTP 状态与业务码，不假定两者相同；代表性失败有既定格式时给示例，通用错误可回链。示例只覆盖必要场景，不穷举所有字段组合。
- 只展开相关规则：列表说明筛选、排序及分页，详情说明不存在的处理，修改说明可改字段及缺失/null 的语义，删除说明软硬删除、关联约束及重复请求行为。幂等、并发或兼容有影响时再写，不为凑齐栏目添加机制。

以下为可复制的单接口版式；移除模板说明后嵌入 LLD，重算设计进度；若保留了接口总览，同步其索引。

### [x] 3. 创建资源

- 回链：[hld #1](hld.md#hld-1)

**结论**

- 新增资源创建接口，成功后返回资源详情。

**依据**

- <实际需求、已确认设计或仓库约定；此演示不构成确认依据>

**接口信息**

| 项目 | 约定 |
|---|---|
| 方法 | `POST` |
| 路径 | `/api/resources` |
| 用途 | 创建一条资源并返回资源详情 |
| 调用方与权限 | <实际调用方、身份校验和授权范围> |
| 请求类型 | `application/json` |
| 成功响应 | `201 Created`，`application/json` |

<如有公共鉴权、响应包装或错误约定，在这里链接已存在的设计点；本例用无包装 JSON 演示，实际项目按既有契约替换。>

**请求参数**

| 位置 | 字段 | 类型 | 必填 | 可为 null | 说明与约束 |
|---|---|---|---|---|---|
| Body | `name` | string | 是 | 否 | 去首尾空白后长度为 1–100 |
| Body | `description` | string | 否 | 是 | 最长 500；缺失或 null 均保存为 null |

**请求示例**

```http
POST /api/resources HTTP/1.1
Host: <服务域名>
Content-Type: application/json

{
  "name": "示例资源",
  "description": null
}
```

<上例仅演示方法、路径和请求体；若项目要求认证 Header，应按真实方式补齐，并以占位符替代凭据。>

**响应字段**

| 字段 | 类型 | 必有 | 可为 null | 说明 |
|---|---|---|---|---|
| `id` | string | 是 | 否 | 服务端生成的资源 ID |
| `name` | string | 是 | 否 | 去首尾空白后的资源名称 |
| `description` | string | 是 | 是 | 资源描述，未提供时为 null |

**成功响应示例**

HTTP 状态：`201 Created`。

```json
{
  "id": "res_001",
  "name": "示例资源",
  "description": null
}
```

**业务行为与异常**

1. 校验请求参数及调用权限。
2. 创建资源，生成 ID，返回持久化后的字段；描述缺失时返回 null。

| 场景 | HTTP 状态 | 业务码 | 调用方处理 |
|---|---|---|---|
| name 缺失、null、空白或超长；description 类型错误或超长 | `400` | `INVALID_ARGUMENT` | 修正参数后重试 |

<鉴权错误及其他已有错误按实际契约补齐或回链；本例的错误体为 code/message 字符串，仅用于演示。>

HTTP 状态：`400 Bad Request`。

```json
{
  "code": "INVALID_ARGUMENT",
  "message": "name 不能为空"
}
```
