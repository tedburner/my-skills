# LLD 模板 — 详细设计

每个有效设计点用相对链接回链实际存在的 HLD 目标；编号在本文内连续分配、不回收，废弃项保留锚点及原因且不计入分母。按主题分组，独立决策可拆成独立设计点；按需求选用下列类别，不适用项注明原因。正文维护现行行为与契约，实施及验证结果引用任务记录。修订直接写回原点并简记变更依据，同步受影响任务及验收。

有新增或变更 HTTP 接口时，使用 [接口条目模板](api-template.md)，按“方法 + 路径”逐接口编号。模块使用 A/B/C 二级标题，编号条目使用三级标题，编号跨模块连续；条目内部默认用加粗标签，供查看器生成清晰的三层目录。下方为正文骨架；生成时移除使用说明、占位提示及无关示例区，重算进度。需要方法、路径对照时才保留接口总览，只列已展开的真实接口，不复制模板中的演示契约。

### 接口组织与公共约定

接口条目按业务模块分组，复制接口模板并按本文已有编号续号。待确认点先展示“要确认 / 建议”，已解决点先展示“结论 / 依据”；用独立加粗标签区分接口信息、请求参数、请求示例、响应字段、成功响应示例、业务行为与异常，正文充分展开且目录聚焦接口条目。确需独立导航的长内容再使用四级标题。不把多份契约塞进一个“CRUD 接口”段落。

公共响应包装、鉴权、分页、错误格式等相同约定可单独设一个有编号的设计点，各接口回链，仅展开差异；接口自身的成功响应示例仍展示完整包装。公共约定只写一次，避免每次变更修改多份副本。新增公共决策点也计入进度和任务覆盖。

接口总览和单接口字段级内容只在 LLD 维护，HLD 保留能力及边界。每个接口条目是否勾选，取决于契约是否已有依据；有争议的权限、兼容性或业务语义才提问，不为 CRUD 数量增加确认轮次。示例、字段表和公共约定必须一致；没有事实依据的字段或错误码明确待定，不把演示值当作真实约定。
